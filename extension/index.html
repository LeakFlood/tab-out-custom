Google Cloud setup

Configure Gmail access

Follow these steps once for every Google OAuth client you want to use.

Before you begin Use the Google account that will manage the Cloud project. You must be able to create or edit a Google Cloud project and access every Gmail address you want to connect.
1

Create or select the Google Cloud project

  1. Open the project selector. Check the project name shown in the top bar: every following step must be completed in this same project.
  2. If needed, click “NEW PROJECT”, enter a name such as “Personal Tab Out”, then click “CREATE”.
  3. Select that project and wait until its name appears at the top of the Console before continuing.
Open the project selector
2

Enable the Gmail API

  1. Open the “Gmail API” page and confirm that the correct project is still selected at the top.
  2. Click “ENABLE”. If the button says “MANAGE”, the Gmail API is already enabled.
Open the Gmail API page
3

Initialize Google Auth Platform

  1. Open “Google Auth Platform → Branding”. If you see “Google Auth Platform not configured yet”, click “GET STARTED”.
  2. Under “App Information”, enter an “App name” such as “Personal Tab Out” and choose a “User support email”, then click “NEXT”.
  3. Under “Audience”, choose “External” for personal Gmail accounts. “Internal” works only for accounts in the same eligible Google Workspace organization.
  4. Under “Contact Information”, enter your email. Under “Finish”, accept the Google API Services User Data Policy, then click “CONTINUE” and “CREATE”.
Open Google Auth Platform
4

Authorize the Gmail test accounts

  1. Open “Google Auth Platform → Audience” and confirm that “Publishing status” is “Testing” if the app remains private.
  2. If the type is “External” and the status is “Testing”, open “Test users”, click “ADD USERS”, add every Gmail address to connect, then click “SAVE”.
  3. In this mode, an address missing from “Test users” cannot authorize access. For multiple accounts, add every address here before connecting them in Tab Out.
  4. In “Testing”, Google limits offline authorization to 7 days, so periodic reconnection is expected. Publishing with the restricted Gmail scope can require Google verification.
Open the Audience page
5

Declare the Gmail permission Tab Out uses

  1. Open “Google Auth Platform → Data Access”, then click “ADD OR REMOVE SCOPES”.
  2. Search for the exact URL below. If it is not listed, use “Manually add scopes” and paste it without changing it.
https://www.googleapis.com/auth/gmail.modify
  1. Select the “gmail.modify” row, click “UPDATE”, then click “SAVE” if that button is shown on the main page.
  2. Tab Out uses this scope to read messages and support read/unread, star, archive, and trash actions. It does not allow permanent deletion that bypasses Trash.
Open the Data Access page
6

Create the Desktop OAuth client

  1. Open “Google Auth Platform → Clients”, then click “CREATE CLIENT”.
  2. Under “Application type”, select exactly “Desktop app”. Do not choose “Web application” or “Chrome extension”.
  3. Under “Name”, enter a recognizable name such as “Tab Out - Brave”, then click “CREATE”.
  4. In the result dialog, immediately copy “Client ID” and “Client secret”. Since 2025, Google might not display the complete secret again; also use “DOWNLOAD JSON” as a backup when available.
  5. Do not create an API key, JavaScript origin, or redirect URI. The Desktop client accepts the local 127.0.0.1 redirect that Tab Out configures automatically with PKCE.
Open the Clients page
7

Save the client in Tab Out

  1. Return to Tab Out, open “Settings → General”, and scroll to “Gmail notifier” at the very bottom.
  2. Under “Shared OAuth client”, paste the “Client ID” and “Client secret” from the same Desktop client, then click “Save shared client”.
  3. Wait until the status says “Configured”, then click “Add with shared client”.
  4. In the Google window, choose the intended Gmail address and approve access. If Google shows an unverified-app warning, continue only when you recognize your own project and the address is listed under “Test users”.
  5. When complete, the Google window closes and a card with the exact account address appears in Settings and in the dashboard Gmail widget.
+

Add multiple Gmail accounts

  1. You normally do not need another project, API activation, or client: the “Shared OAuth client” can connect multiple accounts.
  2. While in “Testing”, first return to “Google Auth Platform → Audience → Test users” and add every new Gmail address.
  3. In “Settings → General → Gmail notifier”, click “Add with shared client” again for each additional account.
  4. In Google’s account chooser, select the new account. If it is not shown, click “Use another account” and sign in with that address.
  5. Repeat once per account. Every address gets its own card, unread count, visibility, filters, and notification preferences.
  6. Use “Add with its own client” only when you want to isolate an account behind another Desktop OAuth client. Keep that client’s Client ID / Client secret pair separate.
Important The “Client ID” and “Client secret” must come from the same “Desktop app” client. These credentials stay in this browser profile’s local storage.

Quick checks when connection fails

  • “Access blocked” or rejected account: check “Audience”, External/Internal, and the exact address under “Test users”.
  • “invalid_client”: if the secret was lost, create a new “Desktop app” client and copy the ID and secret from that same creation.
  • Gmail API error: confirm Gmail API is enabled in the same project that contains the OAuth client.
  • Reconnect requested after 7 days: this is expected for an External project kept in “Testing”.
